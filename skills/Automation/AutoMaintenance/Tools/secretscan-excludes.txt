# secretscan-excludes.txt — BASE excludes, newline-separated regexes passed to
# trufflehog's -x/--exclude-paths flag (verified against the installed
# trufflehog 3.95.8 `filesystem` subcommand: `-x, --exclude-paths=EXCLUDE-PATHS
# Path to file with newline separated regexes for files to exclude in scan`).
#
# Each pattern is matched unanchored against the FULL scanned path, so a bare
# directory-name fragment (e.g. `node_modules/`) matches it at any depth. That
# is safe for the patterns below (vendored deps/git internals/Takeout extracts
# never legitimately appear as a scan ROOT's own ancestor path). It is NOT
# safe for excluding "worktrees" — this repo's own convention checks worktree
# sessions out at <repo-root>/.claude/worktrees/<name>, so if a scan is ever
# run FROM WITHIN a worktree checkout, an unanchored "(^|/)worktrees/" pattern
# would match the scan root's OWN path prefix and silently exclude 100% of
# the scan (verified empirically during E1 development — chunks:0, bytes:0,
# reported as a false "0 secrets" clean run: exactly the failure class this
# slice exists to kill). SecurityAuditor.ts's buildExcludesFile() therefore
# generates the worktrees exclusion DYNAMICALLY per invocation, anchored with
# `^` to the resolved scan root, and appends it to a per-run copy of this
# base file — see runSecurityAuditCheck().
#
# Vendored dependencies — regenerable, never contain hand-authored secrets.
(^|/)node_modules/
# Git internals — packfiles/objects, not source.
(^|/)\.git/
# Google Takeout extracts (YouTube/Chrome history, addresses, device info) —
# large regenerable personal-data archives, already gitignored
# (MEMORY/AppUsage/youtube-takeout-inbox/, MEMORY/AppUsage/youtube-takeout-extracted/
# in .gitignore). Not source, not secrets — just bulky personal exports.
(^|/)youtube-takeout-inbox/
(^|/)youtube-takeout-extracted/
# Jm's vault-policy decision (2026-07-22): ~/.claude/secrets.json is the
# INTENTIONAL secret store (see CLAUDE.md "Secrets and isolation" — all API
# keys/tokens/credentials go there by design, and it is gitignored). Flagging
# its own contents is a false positive by construction, not a real finding:
# 5 of the 73 verified hits from the 07-19 scan were the vault file itself.
# `$` anchors to end-of-path so this excludes exactly `secrets.json`/
# `.../secrets.json`, never a legitimately-scanned lookalike such as
# `mysecrets.json` or `secrets.json.md` (verified in SecurityAuditor.test.ts).
(^|/)secrets\.json$
