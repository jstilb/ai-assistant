# Codex builder

Read this only when the project's builder is Codex (its handoff says "Builder: Codex"). It replaces the session spawn of Orchestrate step 4. The why: `Reference/WHY.md`, section "Workflows/Codex.md".

Make the worktree yourself (`git -C <project> worktree add <path> -b <project>-U<n>`, plus the setup that the project's AGENTS.md names, e.g. `uv sync`), open the unit with `--builder <project>-codex-U<n>`, and start the run in the foreground with `bash ~/.claude/skills/Automation/EndStateLoop/Tools/codex-unit.sh --detach U<n> <worktree> <contract> <board folder> [--add-dir <dir>]…`. It prints `detached pid=<pid> done=<path>` at once; the run is in its own session, so the end of your session does not stop it. Exit 5: that unit's run still runs. Then arm `bash ~/.claude/skills/Automation/EndStateLoop/Tools/codex-unit.sh --wait <board folder> U<n>` with `run_in_background: true`. Its line is the report (exit, minutes, `result=`, `commit=`, thread, Codex weekly %), also in `units/U<n>/codex-done.txt`: the builder ended. The run commits the tree with the `Commit message:` line of `RESULT.md`. A `REFUSED` line: Codex's weekly usage is at `CODEX_USAGE_LIMIT` (default 98 %); the row waits for the reset that the line names. "runner died without codex-done.txt": the run was killed; read `units/U<n>/codex-run.log`, then start the unit again with `--detach`. Then Orchestrate step 5.

A new orchestrator arms `--wait` again for each open Codex unit: it prints the line at once if the run ended (`codex-done.txt`), waits while the pid in `codex-unit.pid` runs, and else reports the died line. Exit 2: the unit has no detached run (it started without `--detach`). Never stop a Codex run because its orchestrator ended. Codex units spend Codex's quota, not Claude's; the examiner stays a Claude session.

A Codex contract never asks for `ps`, `pgrep` or signals to other processes. The memory lock of a project with Codex units is `<board folder>/locks/RUN.lock` (a folder with only locks; the examiner brief names it): pass `--add-dir <board folder>/locks`, and the contract tells Codex to run each heavy step with `runlock.sh` on that lock. Never `--add-dir` the board folder or a folder that holds it (the tool refuses).
