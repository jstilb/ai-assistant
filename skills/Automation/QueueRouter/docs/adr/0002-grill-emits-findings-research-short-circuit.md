# Grill emits the research findings; the autonomous research spawn runs only for ungrilled or opt-in items

The interactive grill session (GrillWithDocs) already explores the codebase, cross-references claims with code, and ends with human-confirmed intent — yet `grill finalize` unconditionally re-ran the 15–30 min autonomous `claude -p` research subagent afterward. Empirically the post-grill pass was pure overhead: across all observed research artifacts, every `skip` verdict came from never-grilled auto-routed items; every grilled item's research returned `implement`. The spawn was also classifier-blocked when finalize ran from an interactive session, hanging the finalize loop (spec-gen itself uses `inference()`, not a nested claude spawn, so research was the sole interactive blocker). The decision: the grill session writes the findings artifact itself, in the exact format the research agent produces (structured findings + `VERDICT` line), and `grill finalize --findings <path>` records it via `attachContext`. `runResearchPhase` short-circuits when `_meta.grillFindingsProvided` is set and the artifact exists — it calls `dispatchResearchVerdict` directly, no spawn. The item still passes through `researching` status; the state machine is unchanged. Finalize without `--findings` keeps the autonomous spawn (backward compatible), and `--deep-research` forces it even with findings present. The short-circuit also disables itself on revision re-entry (`lastRejectionReason` set) so rejected specs get fresh research informed by the feedback.

## Considered Options

- **Always skip research for grilled items** — rejected: some grilled items genuinely need a long autonomous dive (library benchmarking, multi-repo surveys, external research). The `--deep-research` escape hatch and the no-findings fallback preserve that.
- **Fix the classifier-nesting guard instead and keep the spawn** — rejected: even a working spawn is redundant for items the human just researched in-session, and the nesting-guard fix proved fragile (hardened env did not unblock it, reconfirmed 2026-06-12).
- **Treat grill output as context for research rather than as the findings artifact** — rejected: that keeps the spawn and adds a second format; the pipeline already has one findings format with one parser (`parseResearchVerdict`), and the grill can produce it directly.
- **Transition `needs-grilling → generating-spec` directly** — rejected: changes the state machine, breaks the audit trail (`researchedAt`, verdict metadata), and a test explicitly locks that transition as invalid.

## Consequences

- The grill session owns the findings format. ~~A verdict-less artifact defaults to `implement` (existing `parseResearchVerdict` behavior) — acceptable, since a human just confirmed intent.~~ Superseded (commit `eab3f022c0`): `parseResearchVerdict` now returns a `bounce` sentinel when no `VERDICT` token is found, and `dispatchResearchVerdict` holds the item at `awaiting-context` for re-enrichment instead of fabricating a spec from incomplete findings — this applies to grilled items too. See `SpecPipelineRunner.ts` (`parseResearchVerdict`, `dispatchResearchVerdict`) and `ResearchSalvage.test.ts` ("parseResearchVerdict (Phase 6 — no-verdict → bounce)").
- A `skip` verdict can no longer silently archive a grilled item: `dispatchResearchVerdict` holds grill-stamped items at `awaiting-context` and escalates a `manual-<id>` task to "Kaya — Needs Jm". Autonomous research keeps full skip authority over ungrilled items, where it has empirically earned it.
- Interactive `grill finalize` no longer hangs on the common path. ~~The UX/UI stage still spawns `claude -p` for UI-flavored items — that path is unchanged and may still block interactively.~~ Resolved: the UX/UI stage now runs each designer step as a single-shot `inference()` call with inlined context docs (SpecSheet ADR 0007) — no tool-capable nested spawns remain anywhere in the pipeline.
- Research runs that do happen now receive the domain `CONTEXT.md` vocabulary (previously spec-gen-only) and any prior completed research artifact (previously only timeout partials resumed) — revision re-runs no longer start blind.
- `MEMORY/WORK/grill-<id>-findings.md` becomes a durable artifact of each grill, feeding spec-gen via `_meta.researchArtifactPath` exactly as autonomous findings do.
